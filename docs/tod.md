# 时间与天气对齐（Time of Day, TOD）

> 结论先行：源帧可用的时间证据只有一组（太阳方向、颜色、角半径、雾色），对应约 14.5 时的光位；UE 侧的做法是把这组值反解进 Directional Light + SkyAtmosphere + SkyLight，并用一条三列曲线资产驱动三个时段。**只有 14.5 时那一列是证据，另外两列是 [美术] 插值；天空（云与蓝白程度）是当前最大的剩余差距。**

## 状态

| 项 | 状态 |
| --- | --- |
| 源证据 | 完成：太阳方向 / 颜色 / 角半径、雾色、太阳天光比 |
| UE 落地 | 完成：方向 1:1、灯色经大气透射率反算、天光 1.2、三时段曲线 |
| 验证 | 完成：地面太阳色回读、太阳/天光比、三时段截图 |
| 判定依据 | 真实视口截图 + 地面色回读；SceneCapture 一次性截图曝光不同，不用于最终判断 |
| 残余 | 天空半球偏暗、不够蓝白；雾高度衰减未映射；整体略偏暖 |

## 源证据

| 量 | 值 | 标记 |
| --- | --- | --- |
| 指向太阳方向 | (0.530, −0.567, 0.630)，仰角 **39.07°** | [事实] |
| 太阳颜色（地面接收） | (4.337, 3.068, 1.467) | [事实] |
| 太阳角半径 | **0.004675 rad**（角直径 0.5357°） | [事实] |
| 雾色 | (0.307, 0.357, 0.391) | [推断]：shader 中与另一色做 lerp，"雾色"是推断语义 |
| 太阳 / 天光比 | **1.35** | [事实]：受光像素中位数，取灯 Pass 前后差 ÷ 天光 Pass 前后差 |

角半径 0.004675 rad 与 UE `LightSourceAngle` 默认 0.5357° 完全一致（默认值即 2×0.004675 rad），这是判断源帧为 UE 系渲染器的一条旁证。太阳色 (4.337, 3.068, 1.467) 是**地面接收值**，不是大气顶值；同一组数值除以 π 后也出现在水面常数里，属于太阳辐照度而非灯源颜色。

太阳 / 天光比的测法：在同一机位拍三张 HDR——全开、太阳 diffuse+specular 置 0、天光置 0，取受光像素的中位数，用两次差分的比值得到 1.35。这个量用于标定 SkyLight 强度，不是颜色标定。

## UE 实现

1. **方向 1:1**：关卡与源帧同一世界基，方向直接对应仰角/方位角，不做换算。
2. **颜色反算**：把源帧地面色除以 UE 大气在该方向上的地面透射率 T。39° 时 `T = (0.83, 0.70, 0.51)`，于是灯设为 **5.225 lux、颜色 (1, 0.839, 0.549)**，穿过大气后地面实得与源帧一致。
3. **回读校验**：地面太阳色回读 **(4.3366, 3.0677, 1.4666)**，与源帧 (4.337, 3.068, 1.467) 一致。
4. **天光**：SkyLight 设 **1.2**。标定用三张 HDR（全开 / 太阳 diffuse+specular 关 / 天光关）在源帧机位拍，按受光像素中位数求比：天光 12 → 0.17，1.5 → 0.81，0.9 → 1.8，取 1.2 ≈ 源帧 1.35。
5. **雾**：雾色写入 `FogInscatteringLuminance`；亮度默认 0，因为 1:1 写入会把整帧洗白。第二轮把高度雾改成密度 0.02、起始高度 4000 cm，只给远景加冷色雾，近处不洗白。
6. **三时段曲线**：曲线资产 `CT_Restore_TOD`，行 = 仰角 / 方位 / 大气顶太阳色 / 照度 / 天光 / 雾色，列 = 6 / 14.5 / 18.5 时。`ue_tod_apply.py` 提供 `ww61250 <天光强度>`、`hour <h>`、`orig` 三个入口，`orig` 恢复关卡原值。三段共用同一条曲线结构，所以 `hour` 只切换查表行，不改灯光的其它属性。
7. **第二轮画面调整**（与 TOD 耦合，统一收在 `ue_look_restore.py`）：
   - 曝光改为手动、bias 1.0（原自动直方图上限钳在 EV −2.84，压不住过曝）。
   - Bloom 阈值 −1、强度 0.6（源帧 Bloom 阈值≈0.046，强度为 [美术]）。
   - 大气 Mie g = **0.1755** [事实]；Mie 散射回到 UE 默认 0.004（关卡原值把天空压成灰）。
   - 体积云改用 `MI_Restore_VolumetricCloud`，密度 0.01（[美术]；源帧的云烘在天空 cube 里，没有体积云可对）。

三个时段列的性质：

| 时段列 | 性质 | 用途 |
| --- | --- | --- |
| 6.0 | [美术] 插值 | 演示低角度冷光 |
| 14.5 | [事实] 证据列（钟点为假设） | 还原主状态 |
| 18.5 | [美术] 插值 | 演示暖色低角度光 |

## 验证

| 项 | 结果 |
| --- | --- |
| 地面太阳色 | 通过：回读 (4.3366, 3.0677, 1.4666) |
| 太阳 / 天光比 | 通过：1.15–1.35（源帧 1.35），测量噪声 ±0.3 |
| 三时段 | 通过：6 / 14.5 / 18.5 三张，曲线驱动生效 |
| SH 天光 | 通过：换天空后用 `ue_sh_apply.py` 重投影 SH 系数 |
| 曝光 / 调色 | 通过：手动曝光 bias 1.0、Fuji 分级关闭，分带亮度落到源帧 0.85–1.0 |

第二轮分带统计（左 = 调整前，右 = 调整后，目标 = 源帧）：天空 luma/饱和度 107/0.32 → **135/0.16**（源 158/0.22）；中景 106（偏橙）→ **122（中性）**（源 129，偏青）；水面 97 → **112**（源 110）。天空仍偏暗、不够蓝白；整体仍略偏暖。

天光标定有过一次返工：第一次量出的天光需求是 12，原因是 SkyLight 的实时捕获还没更新到新天空；等捕获稳定后同一组测量得到 1.2。之后凡是改太阳或天空，都先等实时捕获稳定再标定。另有关卡自带的 Fuji 色彩分级 LUT 一直开着，与自研 32³ LUT 冲突，第二轮已关掉分级强度，调色统一由 LUT 模块承担。

## 与源的差异

1. **只有 14.5 时那一列是证据**，而且"14.5 点"这个钟点本身是假设——截帧里没有游戏时间。6 点 / 18.5 点是美术插值，用来演示曲线驱动，不是还原。
2. **没有把源帧太阳色直接当灯色**：UE 的天空与雾由灯色驱动，直接给暖色会让整片天发橙。因此做了大气透射率反算，这一步是 UE 侧的适配，源帧没有对应操作。
3. **雾只映射了颜色**：源帧 `cb1[295].y = 0.65` 在 shader 里是 `1 + 0.65·x` 的线性用法，不是 UE 的指数高度衰减，**没有映射**。高度雾的密度与起始高度是 [美术] 选择。
4. **天空是最大剩余差距**：源帧是亮蓝天 + 白云，关卡是偏暖的灰云。源帧的云烘在天空 cube 里，UE 用体积云近似，结构与色彩都对不上；这属于天空模块，本轮没有解决。两者生成路径也不同：源帧天空是预烘的 cube 逐 mip 合成，UE 是 SkyAtmosphere + 体积云实时合成，云的形态与银边无法逐项对齐。
5. **光晕缺失**：源帧塔周围有强光晕（FFT Bloom + 远景 Bloom，6 万 cm 外才叠加），UE 后处理栈没有直接对应。
6. **Rayleigh 直接映射已放弃**：源帧 Rayleigh 常数直接填入会让天空变成平灰，单位与归一化与 UE 散射系数不是同一套，保留 UE 原值。
7. **整体色偏**：源帧偏青、UE 略偏暖，属于天空 + 调色的联合差距，没有单独归因。
